# 自我评价怎么写 —— Few-Shot 模板

**这是所有 `self-eval/<family>.md` 的上位规则。写任何自我评价前先读这里。**
2026-08-24 与用户讨论后定稿。用户原话："不应该再重提之前提过的"。

---

## 核心原则：自我评价 ≠ 项目经历的摘要

一张简历表单里，**项目经历栏已经回答了"你做过什么"**。
自我评价再把 recall@5 72%→96%、pass-all-3 100%→20% 抄一遍，HR 往下滚一屏就看到重复内容，
这个字段等于白占位置。

**自我评价要回答的是另一个问题：你是个什么样的工程师。**

| | 回答的问题 | 内容 |
|---|---|---|
| 项目经历 | 你做过什么 | 事实、指标、技术栈 |
| **自我评价** | **你怎么思考、怎么工作** | **判断力、方法论、工作习惯** |

⚠️ 两个都要避开的极端：
- ❌ **抄项目指标** → 重复，浪费字段
- ❌ **写"积极向上、乐于学习、乐于助人、学习能力强"** → 任何人都能写，等于没写。
  HR 一眼识别为套话，技术岗尤其吃亏。（用户账号里的旧版就是这种，已判定拖后腿。）

---

## 四段式结构（约 350-450 字）

```
【第1段 · 一句话立论】  ← 你的技术判断，越反直觉越好，不超过 2 行
【第2段 · 这个判断怎么来的】← 用经历佐证，但写"我因此学到什么"，不报指标
【第3段 · 为什么适配这家】  ← 把立论接到对方的业务特性上，必须每次重写
【第4段 · 工作方式 + 性格】← 一句话带过，性格只占半句，绝不当主角
```

**为什么这个结构有效**：立论让人记住你；佐证证明你不是空谈；第3段证明你研究过这家公司；
第4段满足"想了解性格"的诉求但不喧宾夺主。

## Few-Shot 示例

### ✅ 示例 1 —— 度小满 · Agent应用研发工程师（金融科技，2026-08-24 实用）

> 我做 AI 应用有一条一以贯之的判断：大模型能力很强，但不能被信任，必须用确定性的东西兜住它。
>
> 这个认知不是想出来的，是量出来的——我做 Agent 评测时发现，前沿模型擅长调用工具，却不擅长规划何时调用；把工具调用换成检索，同一批任务的正确率会断崖式下跌。所以我在做电商导购 Agent 时，排除性需求（"不要日系"）一律交给规则代码强制执行，而不指望模型自觉；在做电力策略系统时，坚持让 LLM 只产数据、不产控制码，安全参数不经过大模型。
>
> 这套习惯放在金融场景我认为特别必要：强监管、高容错成本，出错的代价不是体验差一点，而是真金白银和合规风险。我倾向于先把"模型错了会怎样"想清楚，再决定给它多大权限。
>
> 工作方式上我依赖数据而不是感觉——上线前一定有评测集和对抗测试；性格上乐于协作、习惯主动补位，能接受快速迭代的节奏。

**拆解**：
- 立论 = "大模型不能被信任，要用确定性兜住"（有观点、可辩论、显示判断力）
- 佐证 = PHMForge + LionPick + 珠海瓦特，但**一个数字都没报**，全部转成"我因此怎么做"
- 适配 = 金融强监管、高容错成本 → 立论天然成立
- 收尾 = 半句工作方式 + 半句性格，367 字

### ✅ 示例 2 —— 电商公司（唯品会/得物类）改写方向

> 我做检索和推荐有一个基本立场：用户说不要什么，比说要什么更重要，而这恰恰是模型最容易忽略的。
>
> 做电商导购 Agent 时我发现，"不要日系""华为以外"这类排除性需求，靠 prompt 提醒模型是不可靠的——它会在长对话里逐渐忘记。所以我把这类约束下沉成规则代码强制执行，同时给每句回答标注信息来源，让"这个推荐从哪来"可追溯。商品库里没有的东西，宁可回答"没找到"也不让它编。
>
> 电商的搜索推荐最终是要对转化和复购负责的，用户被推错一次的信任损失，不是靠下一次推准就能补回来。所以我倾向于先把"错误会怎么发生"想清楚，再谈效果优化。
>
> 工作方式上我习惯用评测集说话，上线前必做对抗测试；性格上乐于协作、习惯主动补位。

## 复用流程

1. 读 JD，找出**这家公司的业务特性**（金融=强监管；电商=转化与信任；出行=安全与实时性）
2. 从下面的「立论库」挑一条与该特性最契合的
3. 第2段用 2-3 段经历佐证，**转述认知，不报指标**
4. **第3段必须重写**，把立论接到该公司的业务特性上
5. 第4段基本不变

## 立论库（按 family 备选，都是从真实经历里提炼的，不是编的）

| 立论 | 适用 | 佐证经历 |
|---|---|---|
| 大模型能力强但不能被信任，必须用确定性的东西兜住 | 金融、医疗、工业、任何高容错成本场景 | R1 + P1 + I1 |
| 用户说"不要什么"比"要什么"更重要，而模型最容易忽略这个 | 电商、搜推、导购 | P1 |
| 评测体系要先于优化存在，否则"变好了"只是错觉 | 所有 AI 应用岗、效果向岗位 | R1 + P1 |
| Agent 的瓶颈不在会不会调工具，而在知不知道何时调 | Agent 平台、工作流编排 | R1 + R2 |
| 长程任务里状态管理比推理能力更早成为瓶颈 | Agent 架构、基础设施 | R2 |

⚠️ **立论必须是你真的相信、且能在面试里被追问三层还答得上来的**。
挑一条你能展开讲 5 分钟的，不要挑听起来最漂亮的。
