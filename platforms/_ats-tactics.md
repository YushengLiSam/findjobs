# ATS 浏览器自动化战术

## ⚠️ 先看：两个 agent 的术语对照

本库同时被 Claude Code 和 Codex 使用，两边工具名不同。**看到下面左边的说法，对应右边的工具**：

| 说的是 | Claude Code | Codex |
|---|---|---|
| **驱动用户真实 Chrome**（有登录态、能传文件）| `mcp__claude-in-chrome__*` | ChatGPT 浏览器扩展、`claim` / `nameSession` / `openTabs()` |
| **内置浏览器**（无登录态、传不了文件，别用来投递）| `mcp__Claude_Browser__*` | 「应用内浏览器」 |
| 上传文件 | `file_upload` + input 的 ref | `waitForEvent('filechooser')` + `setFiles` |
| 页面里跑 JS | `javascript_tool` | 同名或 `evaluate` |

`troubleshooting.md` 里 #23~#33 多为 Codex 侧现象（认 ChatGPT 扩展 / setFiles / 应用内浏览器这些词），
Claude 侧未必复现；反之 #1~#22 多为 Claude 侧。**看到不认识的工具名，先查这张表再判断适不适用。**

**每次投递前必读。** 这里每一条都是实际踩过的坑，重踩一次要花 5-15 分钟。

## 1. 坐标缩放 —— 最容易翻车的一条

`computer` 工具的坐标系是**最近一次截图的像素**，而 JS `getBoundingClientRect()` 返回的是 **CSS 像素**。两者不等，截图通常被放大约 1.05 倍。

```
缩放系数 S = 截图宽度 / window.innerWidth      // 例：1547 / 1470 = 1.0524
截图坐标 = CSS坐标 × S
```

**直接拿 JS 算出的坐标去点击 = 会点偏约 5%。** 在 1264px 处偏移 60px，正好从「保存」落到「取消」，一次点击丢掉全部未保存改动。

两种安全做法：
- **首选**：截图后用肉眼从图上读坐标再点（截图坐标系天然一致）
- 或：JS 里算好 `Math.round(x * S)` 再传

按 ref 点击（`computer` 的 `ref` 参数）不受此影响，能用 ref 就用 ref。

## 2. 保存 vs 取消 只隔 ~60px

分区块表单的「取消 / 保存」总是并排在区块右上角。**点错 = 静默丢弃全部改动**，页面只是退回展示态，不会有任何报错，很容易误以为保存成功。

规矩：点保存前**必截图**，看清两个按钮位置再点。点完再核对值是否留存。

## 3. 下拉选择：优先键盘，且必须校验高亮

鼠标点选项经常失败——列表在"算坐标"和"点击"之间会重排/滚动，结果选中相邻项。

**可靠流程：**
```
1. 点开下拉
2. （可搜索的）输入关键词收窄候选
3. 按 Down/Up 移动
4. 【关键】用 JS 读回 class 里的 active，确认高亮就在目标项上
5. Enter
6. 再读回控件显示值，确认真的提交进组件状态了
```

第 4 步不能省。名字互相包含时尤其危险：搜「哥伦比亚大学」会同时命中"不列颠哥伦比亚大学(UBC)"、"英属哥伦比亚大学(UBC)"、"洛斯安第斯哥伦比亚大学"，精确项往往排在最后。

**Enter 有时不生效**（部分 是/否 型下拉），这时改用截图定位后点击选项。

## 4. 认组件库 —— 下拉容器选择器不止一种

同一页面可能混用多套 UI 库，下拉渲染在不同容器里。只查一种会以为"下拉没打开"。

| 库 | 展开的下拉容器 | 选项 |
|---|---|---|
| Ant Design | `.ant-select-dropdown:not(.ant-select-dropdown-hidden)` | `li` |
| rocket-select（PDD 用） | `[class*=rocket-select-dropdown]`（不含 `hidden`） | `[class*=rocket-select-item-option]` |

排查用这句一网打尽：
```js
[...document.querySelectorAll('[class*=dropdown]')].filter(d=>!d.className.includes('hidden'))
```

**rocket-select 的选项在 DOM 里是重复的**（每项两个节点：容器 + content）。过滤掉 `content` 再数索引，否则序号全错：
```js
[...document.querySelectorAll('[class*=rocket-select-item-option]')]
  .filter(o => !o.className.includes('content'))
```

## 5. 日期控件：先试原生 setter，不行再走面板

**两种行为都遇到过，不要假设。**

- **PDD 的日期控件**：点进去打 `2025-09` 无效，还会静默变成当前月份，`form_input` 也无效。必须走面板：
  ```
  点字段 → 面板打开 → 点 «/» 翻年 → 截图确认年份 → 点月份
  ```
  每一步都截图确认，翻年后一定要看清年份再点月。

- **得物（Formily）的日期控件**：React 原生 value setter + `input`/`change` 事件**直接有效**，提交无报错（2026-08-17 实测 5 个日期字段全部成功）。

**流程**：先用原生 setter 写入 → **读回确认** → 值没进去再走面板。省下大量点击往返。

## 6. 分区块表单：编辑态会锁住标签切换

区块处于编辑态（显示"取消/保存"）时，点其他标签页**没有任何反应**，也没有提示。以为是点击失败，其实是被锁了。

**先保存当前区块，再切标签。**

## 7. 联动必填项会在保存时才冒出来

选了某个值会解锁新的必填项，而**保存会静默失败**——不报错，只是把新字段显示出来，区块仍停在编辑态。

实测链条（PDD）：
```
学历类型=海外及港澳台 → 留学期间是否有出境记录
                      → 留学期间是否参加线下授课
                      → 线下授课累计时长
```

**每次点保存后都要检查是否真的退出编辑态**（页面文本里还有没有"取消"）。没退出就是还有必填项没填，往下找新出现的字段。

## 8. form_input 是可靠的，会正确更新 React 状态

按 ref 用 `form_input` 设值，能穿透 React 的受控组件，保存后确实落库（已验证）。文本框和 textarea 都优先用它，比模拟键盘快得多。

**但对日期控件和搜索型下拉无效**（会被设成空），那两类必须走 UI 交互。

## 9. 账号里的旧存档一定要逐字段核

平台账号里存的往往是**上一次投递时的资料**，可能过期一整个学历阶段。这次实测发现的：最高学历还是"本科"、毕业学校还是本科母校、邮箱是已停用的学校邮箱、自我评价结尾写着"如果能有幸获得这次**实习**机会"。

直接投出去 = 和简历自相矛盾，可能被判不符合投递资格。

**规矩：进入表单第一件事是把每个字段读一遍和简历比对，不要假设"账号里有的就是对的"。**

## 10. 展示态可能是折叠的，读不到真实内容

长文本字段在展示态会折叠成 `... 展开`，`innerText` 里读不到内容，容易误判为"保存失败/内容丢了"。先点「展开」再读。

## 11. 上传类字段

- 只有接入真实 Chrome（`mcp__claude-in-chrome__file_upload`）才能上传，内置浏览器不行
- **不要点上传按钮**（会弹出系统原生窗口，看不见也点不了），要用 `file_upload` + 文件输入框的 ref
- 单次总量 ≤10MB
- **已有文件不要擅自替换**：读不到旧文件内容就无法判断哪份更新，而替换是不可逆的。交给用户决定。

## 12. 定位字段用 label，不要用索引

把字段容器读成数组后按下标操作，**只要表单里加了一段子表单（多一段项目/实习/教育），后面所有下标整体偏移**，
值就会写进错误的字段——而且不报错。实测：加第二个项目后，项目名写进了「项目角色」，角色写进了「起止时间」。

```js
const items = [...document.querySelectorAll('<字段容器选择器>')];
const findByLabel = kw => items.findIndex(it =>
  (it.querySelector('<label选择器>')?.innerText || '').includes(kw));
```

**每次操作前重新查一遍 `items`，不要跨操作缓存索引。** 已写错位的字段要先清空再重填。

## 13. 弹层不销毁 —— 按内容认，不要按"可见"认

React 表单的下拉弹层**打开过就一直留在 DOM 里**。按 opacity / display / 顺序挑"当前那个"，
很容易拿到上一个字段的过期弹层，结果把别的字段的候选值填进来。

**按选项内容签名定位**：
```js
const dd = [...document.querySelectorAll('[class*=dropdown]')]
  .find(e => [...e.querySelectorAll('<选项选择器>')]
    .some(x => x.innerText.trim() === '目标选项'));
```
选完再读回该字段的展示值确认。

## 14. 属性选择器可能匹配不到 —— 用 DOM 属性过滤

`input[type=text]` 一个都匹配不到、但页面上全是文本框？很多 React 表单渲染的 `<input>`
**没有显式 `type` 属性**。`.type` 属性会返回默认值 `text`，属性选择器不会。

```js
[...el.querySelectorAll('input')].filter(e => e.type === 'text')   // ✓
el.querySelectorAll('input[type=text]')                            // ✗ 可能为空
```

## 15. 虚拟滚动列表（rc-virtual-list）交给用户

级联选择器里的省市树常用虚拟滚动，程序设 `scrollTop` 无效，很难钻到具体城市。
**别死磕**——填到能填的层级（如「中国大陆」），把精确选择留给用户手点，一句话说明即可。

## 16. 效率习惯

- 能一次读完的信息用一次 JS 全读出来（标签映射、全字段取值、按钮坐标一起返回），别一个字段一次往返
- 改完一个区块立刻核对再保存，别攒到最后
- 截图只在需要看视觉状态时用（点按钮前、确认面板），纯读值用 JS 更快更准
