# Moka HR（app.mokahr.com / app-tc.mokahr.com）— 国内大量公司在用的通用 ATS

```
企业招聘首页  https://app.mokahr.com/campus-recruitment/<企业代号>/<数字>#/
旧版/部分站点 https://app-tc.mokahr.com/campus-recruitment/<企业代号>/<数字>#/
我的简历      #/candidateHome/resume        ← 主表单，一次填好可复用到该企业所有岗位
个人资料      #/candidateAccountInfo        ← 姓名/手机/邮箱在这里改，不在简历页
投递记录      #/candidateHome （头像菜单）
```

已知使用方：**唯品会**（`vipshophr/10039`）、**阳光电源**（`sungrow/94416`）。很多公司共用这套，换公司大概率只是换企业代号。

组件库前缀 `sd-`（Moka 自研）。整页单表单，底部一个「保存」，各区块右上角有「添加 / 删除本条」。

## ⚠️ 最坑的一条：候选人中心的姓名/手机/邮箱在简历页是 disabled

候选人中心 `#/candidateHome/resume` 的 `基础信息` 三个字段全部 `disabled: true`，怎么写都不进去（我在这上面白试了三轮）。
它们属于**账号**而不是简历，要点右上角「**个人资料**」按钮进 `#/candidateAccountInfo`，
每项后面有铅笔图标 → 弹「编辑姓名」对话框 → 填 → 确认。

直接岗位申请页 `#/job/<jobId>/apply` 是另一套表单：未登录时姓名、手机、邮箱会显示为可编辑字段，但页面同时弹登录框；登录后仍要以页面实际状态为准。

- **姓名**：可直接编辑
- **邮箱**：显示「未绑定」，绑定要走邮箱验证码，**交给用户自己做**
- **手机号**：注册时已绑定

## ⚠️ 第二坑：子表单里的字段全是搜索型下拉，不是文本框

学校 / 专业 / 学历 / 年 / 月 都是 `sd-Select`，长得像输入框（没有明显箭头时尤其骗人）。

**`form_input` 和 React 原生 setter 对它们无效，而且会造成两种静默错误：**

1. **误选相邻项**：给学校灌「哥伦比亚大学」，组件自动匹配成了「**哥伦比亚大学教育学院**」（Teachers College，完全另一所学校），界面上还打了勾。同名陷阱与 PDD 的 UBC 一模一样。
2. **写入非法值**：月份灌 `09`，下拉显示「暂无选项」——**月份的合法值是 `9` 不是 `09`**。

正确姿势（真实 UI 交互）：
```
点字段 → 打字过滤 → 【看清候选列表】→ 点精确那一项 → 读回确认
```
**选项出现在字段正下方，截图坐标约 +66px**，同列多项时每项间隔约 38px。
学校这类必须先截图看候选，绝不能盲点第一项。

## 哪些字段可以用 form_input / setter

**顶层纯文本输入框可以**，且保存后确实入库：所在地、最近公司、证件号码、期望城市。
**子表单里的纯文本框和 textarea 也可以**（公司名称/职位名称/工作职责/项目描述），
但 `form_input` 的 ref 很容易失效（DOM 一变就废），实测**直接用 `computer` 打字更稳**。

## 字段地图

| 区块 | 字段 |
|---|---|
| 基础信息 | 姓名 / 手机号码 / 邮箱 —— **全部 disabled，见上** |
| 个人信息 | 性别、工作经验、最高学历、所在地、最近公司、证件类型+证件号码、出生日期 |
| 求职意向 | 当前薪资、期望薪资、期望城市 |
| 工作经历 | 起止时间、公司名称、职位名称、工作职责 |
| 教育背景 | 就读时间、学校名称、专业名称、学历 |
| 实习经历 | 起止时间、公司名称、职位名称、工作职责 |
| 项目经验 | 起止时间、项目名称、职责、项目描述、项目中职责 |
| 语言能力 | 语言类型、掌握程度、听说、读写 |
| 自我描述 | 简介（自由文本） |
| 获奖经历 | 获奖时间、奖项名称 |

**两个自动推导字段**（不用手填，填了也会被覆盖）：
- `出生日期(年龄)` 只读，**填完身份证号自动算出**（可用来反向校验身份证对不对）
- `最高学历` 填完教育背景后变灰，由学历条目推导

**提示语**：教育背景区块顶部写着「硕士、博士学历需填写本科教育经历」——**硕士必须加两条教育经历**。

唯品会候选人中心简历页**没有简历附件上传字段**（`input[type=file]` 数量为 0），这张表本身就是简历；这不是 Moka 全局规则。阳光电源的直接岗位申请页明确要求上传简历，并另有可选附件。

目标岗位：`AI应用工程师`，岗位 UUID `312552cb-bbbf-400a-8552-120ef7e68672`，合肥，2027 届正式批。

- 匿名申请页会强制弹登录框，可用手机号验证码、邮箱验证码或微信登录；登录验证必须由用户参与。

### 官方公开接口的只读核对方法

Moka 根页面首次访问可能连续 302 到自身；先用 cookie jar 访问页面，再复用同一 jar 请求接口。

- 岗位详情：`POST /api/outer/ats-apply/website/job`，正文包含 `orgId`、`siteId`、`jobId`、`locale`。
- 申请表：`GET /api/get_apply_form/<orgId>?device=pc&site_id=<siteId>&applyMode=campus&hireMode=2&jobId=<jobId>`。
- 岗位详情可能返回 `{data, necromancer}`；官网前端使用 `necromancer` 的 UTF-8 字节作为 AES-CBC key，使用根页面 `TurboApply.data.aesIv` 作为 IV，PKCS7 解密。只用于读取公开岗位配置，不用于登录、提交或绕过验证。

## 稳定性：这个页面会卡

- 长文本 `type` 常报 `Input.insertText timed out after 30000ms`，但**文字其实已经进去了**。
  **不要重试**（会打两遍），先用 JS 查 `textarea.value.length` 核对。
- 渲染进程会短暂冻结：**截图通道先挂（`Script injection timed out`），JS 还能用**；等十几秒自己恢复。
  期间可以用 `javascript_tool` 继续读状态。
- **`scrollTo` / `scrollIntoView` 会被组件重置回原位**，算出来的坐标全是视口外的值。
  必须用 `computer` 的 `scroll`（真实滚轮）。约 136px/tick。

## 乐狗游戏（legougames/6163，2026-09-05 实测）

- 岗位申请页 `#/job/<jobId>/apply` 登录后可直接填，表单很短：
  推荐码 / 上传简历 / 姓名·手机·邮箱 / 教育背景（可多段）。
- **底部只有「预览并提交」，没有暂存** —— 填好的内容只在页面状态里，关标签页就没了。
- 简历上传后会自动解析并填充教育经历，但**日期常错**（把硕士填成 2026-12~2026-12）。
  年月都是搜索型下拉，按本文件「第二坑」的姿势逐个点选，**月份是 `9` 不是 `09`**。
- 站内只有一个 AI 相关技术岗：**算法工程师（游戏理解方向）**（模型算法组）。
  另有「游戏运维」属技术类但方向不同。
- 岗位列表是 SPA，点标题不跳转，要取 `a.href` 里的 `#/job/<uuid>` 直接导航。
