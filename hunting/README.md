# 岗位搜寻 SOP（agent 无关，Claude / Codex / 任意 agent 都能跑）

**这份文件是可执行规格,不是说明文档。** 照着跑就行,不要重新设计流程。

配套文件:
- `hunting/lanes.md` —— 10 条搜索赛道的具体分工（每条可独立分配给一个 agent/一轮对话）
- `hunting/prompt.txt` —— 通用前缀 prompt,原样复制,后面接一条 lane 的任务即可
- `../job-leads.md` —— 结果台账,唯一真源
- `../profile/candidate_profile.json` —— 候选人事实
- `../session-log/` —— 已投记录,用来生成排除名单

---

## 两种模式，按用户给的输入选

| 用户给的是 | 走哪个 | 文件 |
|---|---|---|
| **方向**（「帮我找 AI Agent 岗」） | 关键词驱动：10 路赛道全网搜 | 本文件 + `lanes.md` + `workflow.js` |
| **公司名单**（「看看字节、美团、小红书」） | 公司驱动：每家一个 agent 进官网挖 | **`by-company.md`** + `by-company.js` |

两种模式**共用**：硬规则（第 3 节）、链接分级（2.5）、日期规则（2.8）、不预筛（6.5）、交接流程（第 7 节）、台账 `job-leads.md`。

## 0. 一句话流程（关键词驱动）

```
读排除名单 → 10 路并行搜（每路一个 agent）→ 交叉去重 → 抽查验链接 → 写 job-leads.md → 给用户勾选
```

**并行是关键。** 串行跑 10 路要一小时以上,并行几分钟。

- **Claude Code**：用 `Workflow` 工具,`parallel()` 十路。脚本模板见本文件末尾。
- **Codex / 其他**：能开子 agent 就开 10 个；不能就分 10 轮对话,每轮贴 `prompt.txt` + 一条 lane,结果自己攒起来。**不要一轮里串行做完 10 条**——上下文会爆,后面几条质量断崖。

## 2. 排除名单（动态生成，绝不硬编码）

```bash
ls session-log/ | grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}-' | sed -E 's/^[0-9]{4}-[0-9]{2}-[0-9]{2}-//; s/-.*$//' | sort -u
```

**每次跑之前现算，不要在任何文件里写死名单。** 写死的会腐烂——已经腐烂过一次
（名单里 5 家没有 session-log，动态生成永远算不出它们，2026-09-05 已补存根）。

⚠️ **人工协作模式投的（如腾讯 join.qq.com）也必须建 session-log 存根**，
哪怕只有「日期/公司/岗位/状态」四行。没有存根 = 排除名单里没有 = 下次重复劳动。

把算出的名单注入 prompt 的 `{{EXCLUDE}}` 占位符。

## 2.5 ⚠️ 链接必须直达 JD（用户 2026-08-29 定的硬要求）

**交付物是「打开就能看到岗位职责」的链接。** 用户的动作流是：
点开链接 → 读 JD → 觉得贴 → 才登录投递。
所以给一个新闻稿链接 = 让用户白点一次，等于没找到。

### 链接分级（只有 A 级能直接交付）

| 级 | 是什么 | 例子 | 能不能交？ |
|---|---|---|---|
| **A** | **岗位详情页**，打开就是职责/要求 | `jobs.bytedance.com/campus/position/<id>/detail`<br>`zhaopin.meituan.com/web/position/detail?jobUnionId=<id>` | ✅ 直接交 |
| **B** | **官方岗位列表 + 精确筛选参数**，打开能看到目标岗在列表里 | `talent.baidu.com/jobs/list?keyword=智能体`<br>飞书站带 `project=<校招项目id>` | ✅ 可交，但必须在备注写「进站后搜 XX」 |
| **C** | 官方招聘站首页 | `career.huawei.com/.../campus-recruitment.html` | ⚠️ 仅当 A/B 都拿不到；备注必须写清进站后怎么搜 |
| **D** | **新闻稿 / 聚合站 / 牛客帖 / 公众号转载** | `leiphone.com/...`、`wondercv.com/xiaozhao/...`、`quanzhi.com/notice/...`、`campus.niuqizp.com/...`、`nowcoder.com/feed/...` | ❌ **绝不作为主链接交付** |

**D 级只能当证据用**，放在 `batch_evidence` / `notes` 里说明「届次信息来自哪」，
**不能填进 `url` 字段**。

⚠️ **而且 D 级页面的「内容」也不可信，不只是链接不能交。**
2026-08-29 实测翻车：wondercv 列出快手「前线部署工程师（FDE）」，
调官方 API 查遍 261 个 2027 届岗位，**含「前线部署」的 0 条**——那是聚合站自己归纳的名字。
它写的截止日 2027-02-08 官方也查无此据（官方 closeTime 为 null，口径是"招满即止"）。
**岗位名和截止日一律以官方站/官方 API 为准。**

💡 **抓不到 SPA 列表时先找官方 JSON API**，比解析页面可靠得多，能一次拉全量做匹配。
已验证：快手 `POST campus.kuaishou.cn/recruit/campus/e/api/v1/open/positions/simple`。

### 拿不到 A 级怎么办

1. 从 D 级页面里找官方链接——新闻稿和聚合站通常会附原始投递入口
2. 搜 `<公司> 校招 官网` 找到官方 career 站，再站内搜岗位名
3. 飞书招聘 SPA 抓不到列表时：**URL 里的 `project=<id>` 参数就是校招批次 id**，
   带上它的列表页算 B 级，可交
4. 实在只有 C 级：交，但备注必须写「进站后在搜索框输 `Agent`」这种可操作指令
5. **链接死了或打不开 → 这条 lead 作废**，宁可不交

### 每条交付前自检

- [ ] 这个 URL 打开后，**第一屏能看到岗位职责吗？**（A级）
- [ ] 不能的话，能看到**目标岗位在列表里吗？**（B级）
- [ ] 都不能 → 降级或丢弃，别拿新闻稿凑数

## 2.8 ⚠️ 日期：先跑 `date`，且只存事实不存推导值

**开跑第一件事**：

```bash
date "+%Y-%m-%d"
```

不要凭上下文推断今天几号。**这条已经犯错两次**（session-log 日期写错、倒计时算错 7 天）。

**存截止日，不存「剩几天」。** 天数是「相对现在」的量，写进数据当场就开始腐烂：
- ✅ `deadline_iso: "2026-09-15"`
- ❌ `days_left: 17`

同理，`届别判断`（2027届窗口是不是还开着）、`已过期` 这些也都要现算。

**产物要自带陈旧提醒**：把扫描日期存进结果里，展示时算 staleness。
校招岗位「招满即止」的居多，一周前的清单已经不能全信了。

## 3. 硬规则（反幻觉,一条都不能松）

1. **URL 必须真实出现在搜索结果或实际访问过的页面里。绝不编造。**
   拿不准就 `confidence: low` 并在 notes 说明。**宁可少报,不可假报。**
   ⚠️ 这条只管**真实性**（URL 和届次不能编）,**不是**允许你按"够不够贴"筛掉岗位——
   相关性上的规则恰好相反：**宁可多给,不可漏报**（见 6.5 节）。
   拿不准的岗位要交出去,但要如实标 confidence 和链接等级。
2. **`batch_evidence` 必须引用页面原文短句**证明对 2027 届开放。
   这条是防时效性污染的核心：搜索引擎里 2025 年发布的 2026 届信息量极大,极易混进来。
   **凡是 2025 年发布的 2026 届信息一律丢弃**,除非页面明确写了 2027 届批次已开。
3. **只找到公司级「2027届校招启动」公告也收**,`title` 写 `校招已启动-需进站搜岗`。
4. **绝不编造截止日期**。查不到就写「未知」。
5. 排除名单里的公司直接跳过。

## 4. 输出格式

每条 lane 返回 JSON：

```json
{
  "leads": [{
    "company": "…", "title": "…", "city": "…",
    "keywords_hit": ["Agent","RAG"],
    "url": "…",
    "platform": "飞书招聘/Moka/北森/官网自建/牛客/未知",
    "deadline": "…或「未知」",
    "batch_evidence": "引用原文短句证明2027届开放",
    "confidence": "high|medium|low",
    "notes": "…"
  }],
  "dead_ends": "查了但没结果的来源及原因,一两句"
}
```

`dead_ends` 不是可选项——**它直接写进 `job-leads.md` 的「查过没岗的」表,避免下次重复劳动。**

## 6. 结果处理（搜完之后）

1. **交叉去重**——多路会搜到同一家,按 `公司+岗位名` 归并,保留 confidence 最高的那条
2. **链接解析（必做，不可省）**——把每条的 url 按 2.5 节分级。
   **凡是 D 级（新闻稿/聚合站/牛客帖）必须解析成 A 或 B 级**，解析不出就降级到 C 或丢弃。
   这一步通常要再跑一轮并行 agent，值得——用户点开的每一个链接都应该是 JD。
3. **抽查验链接**——A 级的抽 5 条真实打开确认，发现死链或内容不符就把该 lane 全部结果降级重查
4. **写台账**——追加到 `../job-leads.md`,`dead_ends` 写进「查过没岗的」表
5. **全量交付给用户**——见下方 6.5 节。**不做相关性预筛**

## 6.4 投之前先查岗位还在不在

台账放几天，「招满即止」的岗就可能已经关了。**投前跑一次存活性校验**，
判断标准和批量查法见 [`../scripts/check-liveness.md`](../scripts/check-liveness.md)。

已关闭的用 `../scripts/set-status.sh "<公司>" "<岗位>" 过期` 改状态，**不要删行**——
留着能防止下次重复挖同一个岗。

## 6.5 ⚠️ 不预筛：只要相关就全给（用户 2026-08-29 定的）

**判断「贴不贴」是用户的活，不是 agent 的活。**
agent 擅长的是把网上散落的岗位捞全，不是替用户做取舍。
一个被 agent 判成"不太贴"而没交出去的岗位，用户永远不知道它存在——**漏报是不可逆的**。

### 规则

- **只要沾 AI/大模型/Agent/算法/研发，就交出来**，别自己判断"这个可能不够贴"
- **不设条数上限。** 30 条就交 30 条，60 条就交 60 条
- **不因为置信度低就丢弃**——标上 🔴 交出去，让用户决定要不要点开
- **不因为岗位名不带 Agent 就丢弃**——很多贴的岗位叫"AI应用研发""大模型算法""解决方案架构师"

### 两条"宁可"别搞混（不同轴，都要遵守）

| 轴 | 规则 | 为什么 |
|---|---|---|
| **真实性** | 宁可少报，不可假报 | 编造的链接和届次会让用户白跑，且污染台账 |
| **相关性** | 宁可多给，不可漏报 | 贴不贴是用户的判断，漏了用户就没机会知道 |

**不冲突**：拿不准的岗位要交（相关性），但要如实标注置信度和链接等级（真实性）。
真正该丢弃的只有两种：**确认是往届的**、**链接死了的**。

### 长清单怎么组织才不难读

不预筛不等于甩一坨。**分组 + 每条一行**：

1. **先按「岗位名直接命中」分层**——JD 或岗位名带 Agent/RAG/FDE 的排最前，
   泛 AI 岗排后面，但**都要在同一份清单里**
2. **组内按截止日排**，30 天内的标 ⏰
3. **每条一行**，不写长段落：`公司 | 岗位 | 城市 | 剩余天数 | 直达链接 | JD原文一句`
4. **推荐理由用 JD 原文**，别用主观形容词——
   「JD 写了 tool-calling + RAG」比「方向匹配」有用得多
5. 如果 agent 有倾向性看法，**单独在清单后面写一小段**，不要靠删条目来表达

## 7. 交付与投递流程（人机怎么交接）

### 全流程

```
[agent] 搜岗 → 解析成直达 JD 链接 → 交清单
                                        ↓
[用户]  逐条点开 JD → 判断贴不贴 → 挑出要投的
                                        ↓
[用户]  在要投的站点登录（验证码本人输）
                                        ↓
[agent] 接手填表 → 逐区块保存 → 停在提交前
                                        ↓
[用户]  过目 → 本人点提交
                                        ↓
[agent] 回写知识库（见 CLAUDE.md 回写清单）
```

**agent 只在第 1 步和第 4 步动手。判断岗位贴不贴、登录、点提交，都是用户的活。**

### 交清单的格式

**全量给，不预筛**（见 6.5 节）。每条必须有：

```
| 公司 | 岗位名 | 城市 | 截止(剩几天) | 直达JD链接 | 一句话为什么贴你 |
```

- **链接必须是 A 级**（见 2.5 节）。B/C 级要在同一行标出「进站后搜 XX」
- **一句话推荐理由要具体**——「JD 原文写了 tool-calling + RAG」比「方向匹配」有用得多
- **按「岗位名直接命中」分层，组内按截止日排**，30天内的标 ⏰
- **不删条目**。拿不准的标 🔴 交出去，让用户自己点开判断

### 登录边界（红线，任何 agent 都不能越）

**验证码绝对不碰。** 这和「绝不点最终提交」同级，没有绕法，
不因为「粘贴板会自动同步」而改变。

用户挑好岗位后：

1. agent 导航到该站登录页
2. agent 填手机号 —— **从 `../profile/candidate_profile.json` 的 `基本信息.手机号码` 取，不要在本文件写明文**
   （本文件设计成可复制给其他 agent / 可公开，不放任何 PII）
3. agent 点「发送验证码」
4. **停下，明确告诉用户「验证码到了，你输一下」**
5. 用户输 6 位数字 + 点登录
6. agent 接手，进入填表流程（见 `../CLAUDE.md` 标准流程）

已登录过的站点 cookie 还在就跳过 1-5。**第 1 层信息源（官网/搜索/GitHub 聚合）
完全不需要登录，先把这层榨干再考虑要登录的。**

## 8. Claude Code 执行模板

```js
const results = await parallel(
  LANES.map(s => () => agent(COMMON_PROMPT + s.task, { label: s.key, schema: SCHEMA }))
)
```

`COMMON_PROMPT` = `hunting/prompt.txt` 全文；`LANES` = `hunting/lanes.md` 的 10 条；`SCHEMA` = 第 4 节的 JSON schema。
完整可跑脚本见 `hunting/workflow.js`。

## 9. Codex / 其他 agent 执行方式

能开并发子 agent 就 10 个并发。不能的话：

```
开 10 轮独立对话,每轮：
  贴 hunting/prompt.txt 全文
  + 贴 lanes.md 里的一条 task
  + 「按第4节 JSON 格式返回」
把 10 份 JSON 攒到一个文件,再执行第 6 节的结果处理
```

**别在一轮里串行做完 10 条。**
